# Chapter 03. 명령어

> 컴퓨터는 **명령어를 처리하는 기계**이다. 

> 하지만 컴퓨터는 Python, C 같은 고급 프로그래밍 언어를 직접 이해할 수 없다.  

> 즉, 프로그래밍 언어는 **사람이 이해하기 위해 만들어진 언어(고급 언어)** 이고, 컴퓨터가 이해하고 실행하기 위해서는 반드시 **명령어로 이루어진 언어(저급 언어)** 로 변환되어야 한다.

---

## 1. 고급 언어와 저급 언어

- **고급 언어**: 사람이 이해하기 쉽게 만들어진 프로그래밍 언어 (Python, C 등)
- **저급 언어**: 컴퓨터가 직접 이해하고 실행할 수 있는 언어로, 명령어로 이루어짐

### 저급 언어의 종류

| 구분 | 특징 |
| :--- | :--- |
| **기계어** | • `0`과 `1`로 이루어진 언어<br/>• **CPU가 직접 이해하고 실행할 수 있는 유일한 언어** |
| **어셈블리어** | • 기계어와 **1:1로 대응**되는 언어<br/>• 기계어보다 사람이 읽고 쓰기 편함 |

> 💡 **참고**: 임베디드 개발자, 게임 개발자, 정보보안 개발자는 하드웨어 제어 및 분석을 위해 어셈블리어를 많이 이용한다.

---

## 2. 고급 언어가 저급 언어로 변환되는 방법

고급 언어로 작성된 소스 코드는 **컴파일러**나 **인터프리터**에 의해 저급 언어로 변환되어 실행된다.

| 비교 항목 | 컴파일러 (Compiler) | 인터프리터 (Interpreter) |
| :--- | :--- | :--- |
| **변환 방식** | 소스 코드 **전체**를 한 번에 저급 언어로 변환 | 소스 코드를 **한 줄씩** 읽으며 변환 및 실행 |
| **오류 처리** | 컴파일 중 오류가 발생하면 **소스 코드 전체 실행 불가** | 한 줄씩 실행하므로 오류 전까지는 정상 실행 |
| **대표 언어** | C언어 등 | Python 등 |

### 소스 코드 변환 및 실행 과정
```text
[ 소스 코드 ] ──(컴파일)──> [ 목적 파일 ] ──(링킹)──> [ 실행 파일 ]
```
- **목적 파일**: 목적 코드로 이루어진 파일 (컴파일 결과물)
- **실행 파일**: 실행 코드로 이루어진 파일
- **링킹(Linking)**: 여러 목적 파일들을 묶어 하나의 **실행 파일**로 완성하는 과정

## 3. 명령어의 구조: 연산 코드와 오퍼랜드

명령어는 크게 **무엇을 수행할지**를 나타내는 연산 코드와, **연산에 사용할 대상**을 나타내는 오퍼랜드로 구성된다.

```text
┌───────────────────────────────┬───────────────────────────────┐
│       연산 코드 (Opcode)       │       오퍼랜드 (Operand)       │
│      "무슨 연산을 할 것인가?"   │    "어떤 데이터를 연산할 것인가?"│
└───────────────────────────────┴───────────────────────────────┘
```

1. **연산 코드 (Opcode)**: 명령어가 수행할 연산
2. **오퍼랜드 (Operand)**: 연산에 사용할 데이터 또는 **데이터가 저장된 위치**
   > 📌 오퍼랜드는 연산할 데이터가 **어디에 있는지** 알려주는 역할을 한다.

### 기본적인 연산 코드 4가지 유형

| 연산 유형 | 주요 명령어 예시 | 역할 및 설명 |
| :--- | :--- | :--- |
| **산술 / 논리 연산** | `ADD`, `SUBTRACT`, `AND` | 덧셈, 뺄셈, 논리곱 등 계산 수행 |
| **제어 흐름 변경** | `JUMP`, `HALT`, `RETURN` | 실행 순서 변경, 조건 분기, 종료 등 |
| **데이터 전송** | `MOVE`, `STORE`, `PUSH` | 메모리/레지스터 간 데이터 복사 및 스택 이동 |
| **입출력 제어** | `READ`, `WRITE` | 입출력 장치로부터 데이터 읽기 / 쓰기 |

## 4. 주소 지정 방식 (Addressing Modes)

명령어 내 오퍼랜드 필드의 한정된 비트 수로 인해 데이터를 직접 넣기보다  **데이터의 위치(유효 주소)** 를 가리키는 방식을 주로 사용한다.

| 주소 지정 방식 | 오퍼랜드 필드에 명시하는 내용 | 특징 |
| :--- | :--- | :--- |
| **즉시 주소 지정 방식** | 연산에 사용할 **데이터 자체** | 데이터 크기 제한이 생기지만, 메모리를 찾지 않아 **속도가 가장 빠름** |
| **직접 주소 지정 방식** | 데이터의 **유효 주소 (메모리 주소)** | 오퍼랜드에 유효 주소를 직접 명시하여 메모리 참조 |
| **간접 주소 지정 방식** | 유효 주소의 **주소 (메모리 주소)** | 메모리를 두 번 거치므로 속도는 느리지만 표현 범위가 넓어짐 |
| **레지스터 주소 지정 방식** | 데이터가 저장된 **레지스터의 주소** | CPU 내부 레지스터를 직접 참조하여 빠른 접근 가능 |
| **레지스터 간접 주소 지정 방식** | 유효 주소가 저장된 **레지스터의 주소** | 레지스터에 메모리 주소를 저장해 두고 해당 주소를 참조 |
